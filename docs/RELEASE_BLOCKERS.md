# Outstanding reproducibility review items

1. **Licence selected.** Owner-selected CC BY 4.0 is applied to author-owned material. LICENSE and NOTICE.md record its text and scope. Third-party terms remain separate.
2. **Dataset source/rights review.** The FLCHAIN/NWTCO cache mechanism was resolved by inspecting installed and upstream pycox code: the project reads raw caches, not pycox's default processed frames. An explicit acquisition script and observed cache hashes/row counts are now included. FLCHAIN=7,874 and NWTCO=4,028 are confirmed locally. A fresh provider download has not been compared with those historical hashes. MUSIC provenance is SETTLED, 2026-09-05: Ren et al. describe MUSIC as a user-lifetime analysis over the Last.fm 1K-user listening dataset (Celma, 2010), where the event is a user's return visit and the duration is the gap between visits. It is not KKBox and not churn. The loader comment is corrected. **A larger question is now open in its place.** Ren et al. describe the source as about 1,000 users, while the loader reads 2,796,646 rows. If those rows are visit intervals from ~1,000 users they are repeated measures within user, and since splits randomise over rows the same user appears in train and test, which would understate every standard error on this cohort. The `.yzbx` files carry no user identifier, so this cannot be checked from the distributed data and needs the DRSA authors or the original Last.fm mapping. Until then treat drsa/music standard errors as lower bounds. FLCHAIN=7,874 and NWTCO=4,028 remain confirmed locally against historical hashes; a fresh provider download has still not been compared.
3. **Simulation seed limitation.** RESOLVED FOR FUTURE RUNS, 2026-09-05; the historical limitation stands. E8/E7/E6c/E6d seeded from `hash()` on tuples containing strings. Python salts string hashing per process, so those seeds differed on every run: the same tuple returned 561268085 and 2230517452 on two consecutive interpreters. The original PYTHONHASHSEED was not recorded, so **the published cells cannot be regenerated exactly** and any rerun is a new experiment. Within a single run all cells shared one salt, so comparisons inside each table remain valid. Seeding now uses `src/kanrel/stats.py::stable_seed`, CRC32 over a canonical encoding, verified identical across processes; runs from this version forward are reproducible. E5 and E6 were never affected, their tuples being numeric.
4. **Correlation definition.** RESOLVED, 2026-09-05, as a documented revision. The audit was correct: `argsort(argsort(x))` assigns ordinal ranks and breaks ties by position, while Spearman's coefficient averages tied ranks. The same defect was present in five files, not one — `crossover.py`, `nuisance_dim.py`, `ordering_variable.py`, `simulations.py`, `why_gain.py` and `paper/figures.py`. All now import a single definition from `src/kanrel/stats.py`, checked against `scipy.stats.spearmanr` on 200 deliberately tied samples. On the same 27 printed cells the E8 correlations become -0.1469, +0.8745 and +0.3777, and the out-of-sample residual ordering becomes 0.853. The manuscript reports the average-rank values and states the previous ones alongside; `results_raw/experiments/simulations_e8.txt` carries the same note. The ranking of the three concentration measures is unchanged and no conclusion moves.
